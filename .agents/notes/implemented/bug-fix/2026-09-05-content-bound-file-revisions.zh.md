# Agent Note: 与内容绑定的本地文件版本

Status: implemented

[English](2026-09-05-content-bound-file-revisions.md) | 中文

## 问题

Windows 读取可能在不改变文件内容的情况下推进访问时间和 ctime。因此，读取前取得的元数据观察记录可能拒绝随后对未变化文件的编辑。仅移除 ctime 又会失去对恢复 mtime 的等长重写的防护。

## 决策

[本地文件系统快照](../../../../packages/fs/fs-local/src/snapshot.ts) 将不可变版本绑定到实际消费的原始字节，以及已打开文件的身份、大小、写入时间和基本权限。完整 SHA-256 独立于读取引起的元数据变化来区分内容变化。观察记录来自读取完成，而不是稍后未经检查的 stat。

[文件系统约定](../../../../docs/subsystems/filesystem.zh.md#content-bound-reads-provider-contract) 将版本化读取设为可选能力。仅支持元数据的提供方保留现有行为，本地旧式 token 保持严格检查。内容防护的编辑匹配已验证的字节，替换在暂存完成后重新验证。变更结果描述实际写入的字节，而不是发布后 stat 所见的无关字节。

## 考虑过的替代方案

**从元数据 token 中移除 ctime。** 这会放过恢复 mtime 的原地等长重写，却没有建立内容相等性。

**读取后重新 stat，或在可变元数据键下缓存摘要。** 前者可能认可未见字节；后者可能把旧会话的观察记录重新绑定到另一会话的读取。

**抑制 Windows 时间戳更新。** 基于句柄的抑制需要额外的写属性权限，全局策略变化则影响无关应用。这两者都不应属于只读操作。

## 结果与影响

快照扫描整个文件，包括显示窗口之外的字节。内容防护的变更扫描两次；最后一次扫描不保留内容。[提供方限制](../../../../packages/fs/fs-local/README.zh.md#known-limitations-and-deferred-work) 包括整文件编辑缓冲，以及最终验证到发布之间仍存在的外部写入窗口。这不是内核级比较并替换。

[回归测试](../../../../packages/fs/fs-local/tests/snapshot.spec.ts) 覆盖恢复 mtime 的重写、不可变观察记录、路径替换、暂存竞态、取消、解码与原始字节上限。哈希和版本保留在内部，不出现在面向模型的错误中。
